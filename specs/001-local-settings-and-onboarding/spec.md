# Feature Specification: Local Settings and Onboarding

**Feature Branch**: `deepcode`（本轮未新建或切换分支）
**Feature Directory**: `specs/001-local-settings-and-onboarding`
**Created**: 2026-10-10
**Status**: MVP 验收收敛中；完成状态见 tasks.md，不代表最终运行验收
**Input**: EduAgent v3.0 Local PC Edition 规划请求；D01–D08。

## Context and Scope

本批让 Windows 用户在本机浏览器完成配置、诊断和初始化，无需手工创建或编辑 .env。保留 Python 后端、现有 AI/业务服务、数据库、Redis、Docker 验证和 Gradio 业务入口。设置流程不依赖业务登录或可用数据库；业务入口仍沿用原登录和权限。

本 Feature 包括环境隔离、配置及安全凭据服务、Provider 注册/连接测试、Bootstrap、最小 React 设置界面和两种交付验证。排除 Rust 迁移、账号表删除、完整取消 JWT/RBAC、StudentProfile 数据迁移、全业务 React 重写、Gradio 退役、Prefix Cache T125–T132、数据库一体安装器、自动重建历史向量和公网/局域网部署。

历史规格中的 v1/v2 约束按版本保留；本批只替代配置来源、设置入口和启动分层合同。用户与角色、课程归属、审核、考试分值、结果最终化、文件授权继续生效。后续替代条件见 [plan.md §11](plan.md#future-roadmap)。

### Session 2026-10-19 — 本地 MVP 验收范围

- 当前交付目标：可实际运行、完成首次配置、执行真实 AI 业务并安全保存/恢复数据的 Windows/Docker 本地 MVP；不宣称企业生产级交付。
- 严格启动 SLO（含原后续 <10 秒）改为非阻断优化目标；测量边界和真实超标事实保留。正常启动、真实浏览器渲染/交互、退出、端口与资源释放仍必验，卡死或泄漏不得豁免。

- T238 按独立数据安全证据验收，不依赖 T234 的性能、跨用户测试或重复首启次数；实际包兼容、凭据/快照/索引/配置恢复和失败闭锁仍须满足。T239 保留首次配置闭环、真实 Provider 最小业务、核心评分/人工复核、双交付及 G0–G7 的相关质量要求；缺任一核心证据不得完成。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 隔离环境并识别实际配置 (Priority: P1)

操作者选择 Development、Test 或 Demo，查看本次实际使用的数据库、文件目录和配置来源，避免测试影响教学资料。

**Why this priority**: 后续配置保存、验证和清理都必须有确定的环境边界。
**Independent Test**: 三套隔离资源分别保存不同标记，切换环境及执行测试清理后，其余两套数据、密钥和文件不变。

**Acceptance Scenarios**:

1. **Given** 尚未初始化，**When** 启动 Windows 应用，**Then** 使用明确标示的 Development 本地工作环境；Test 必须显式选择，不能因测试入口缺配置而使用开发资源。
2. **Given** 某项配置被启动环境覆盖，**When** 查看或修改该项，**Then** 界面显示实际来源、覆盖值的脱敏视图和修改不生效的原因。
3. **Given** Test 指向非测试数据库或目录，**When** 运行或清理测试，**Then** 在写入之前拒绝并给出目标不匹配信息。

### User Story 2 - 配置模型并安全检测 (Priority: P1)

操作者设置默认模型和必要的任务覆盖，安全管理凭据，在明确费用的情况下检测目标能力。

**Why this priority**: 去除手工密钥配置，同时避免把可填写误认为可运行。
**Independent Test**: 在业务数据库不可用时，使用受控替身完成配置保存、八类诊断和失败保护；真实连接另行显式启用。

**Acceptance Scenarios**:

1. **Given** 未配置任何云模型，**When** 保存非敏感草稿或设置本地模型，**Then** 不强制填写无关云密钥，草稿不被误报为 AI Ready。
2. **Given** 默认模型有效，**When** 出题选择覆盖模型，**Then** 出题使用覆盖，未覆盖的主观阅卷仍使用默认模型；Reviewer 保持规则复核。
3. **Given** 有有效配置，**When** 新候选连接测试失败或取消，**Then** 原有效配置和凭据引用保持不变。
4. **Given** Windows 用户新增/替换密钥，**When** 重启并读取设置，**Then** 后端可使用受控凭据，页面只显示状态，不能读取原文。
5. **Given** Docker 用户修改凭据，**When** 查看设置，**Then** 清晰提示外部管理；只读挂载失败不能偷偷改存普通配置。
6. **Given** 自定义兼容服务仅支持文本，**When** 请求图像、Embedding 或结构化业务能力，**Then** 分别检测并拒绝不支持的任务，不按供应商标签推断。

### User Story 3 - 首次启动与中断恢复 (Priority: P1)

用户双击启动后能先看到设置和诊断，依次完成目录、数据库/Redis、模型设置和初始化。

**Why this priority**: 缺少任何模型密钥或数据库配置时仍必须能修复问题。
**Independent Test**: 空配置、数据库离线和初始化中断三种初态均能打开设置；修复后重启继续，业务状态始终真实。

**Acceptance Scenarios**:

1. **Given** 数据库、模型或 JWT 配置缺失，**When** 启动，**Then** Setup Ready 可显示设置；Business Ready 和各 AI 任务就绪状态独立显示。
2. **Given** 核心依赖未就绪，**When** 请求业务操作或直接调用旧业务入口，**Then** 明确拒绝；设置可达不等于业务健康。
3. **Given** 初始化失败，**When** 重新打开或重启，**Then** 恢复已保存步骤，重新检查当前依赖状态（不自动重测付费模型），不记录虚假完成。
4. **Given** 未取得本机设置授权的浏览器或跨源请求，**When** 写配置、检测模型或启动初始化，**Then** 拒绝操作。
5. **Given** 已具备业务依赖但未配置 AI，**When** 完成基础初始化，**Then** 可明确选择稍后配置 AI；允许不依赖 AI 的现有授权操作。

### User Story 4 - 持续使用设置中心 (Priority: P2)

用户查看环境、依赖、模型、密钥和诊断，修改后明确知道哪些已生效、哪些待重启。

**Why this priority**: 首次初始化以后仍须可维护并可恢复。
**Independent Test**: 同时打开两个设置页，验证过期编辑冲突、覆盖来源、需要重启、失败恢复和凭据重录。

**Acceptance Scenarios**:

1. **Given** 两个页面持有同一配置修订，**When** 依次保存，**Then** 第二次冲突得到明确提示，不覆盖第一次修改。
2. **Given** 数据库或持久目录改变，**When** 保存并申请激活，**Then** 标记需要重启并说明现有数据未搬迁；有运行任务时不强制中止。
3. **Given** 密钥不可解密、外部 Secret 丢失或服务拒绝密钥，**When** 查看配置，**Then** 区分不可用、缺失和无效，提供重新录入或外部轮换路径。
4. **Given** 导出诊断或备份业务数据，**When** 保存产物，**Then** 不包含任何凭据原文，不声称业务恢复同时恢复密钥。

### User Story 5 - 配置变化保护教学业务 (Priority: P1)

教师修改配置后，进行中的任务和历史成绩保留真实使用的模型、提示版本与结果语义。

**Why this priority**: 模型配置不能破坏评分一致性、暂停恢复或索引语义。
**Independent Test**: 一次阅卷暂停后修改模型、重启、恢复，确认原运行绑定不变；以有历史向量的库验证不兼容切换被阻止。

**Acceptance Scenarios**:

1. **Given** 运行已绑定配置 A，**When** 激活 B，**Then** 新任务使用 B，原运行及其恢复继续 A；A 的凭据不可用则准确报阻塞，不改用 B。
2. **Given** 已有向量，**When** 选择不同维度或无法证明兼容的模型，**Then** 拒绝激活向量链路，保留原索引并指明独立重建需求。
3. **Given** 客观题或待人工复核成绩，**When** 切换配置，**Then** 客观题仍不调用模型，待复核结果仍不进入最终成绩。
4. **Given** 旧运行或向量没有完整来源记录，**When** 接纳到新版，**Then** 保留历史未知，不伪造旧模型；接纳规则与用户确认记录可追溯。

### User Story 6 - 可交付且可验证 (Priority: P2)

维护者用 Windows 包和 Docker 验证同一设置合同，在隔离环境记录可复现证据。

**Why this priority**: 源码可用不能替代包内资源、真实凭据存储和部署验证。
**Independent Test**: 两种交付分别跑空配置向导、依赖故障、正常初始化、退出/重启与持久化，保存包、环境和结果回执。

**Acceptance Scenarios**:

1. **Given** Windows 安装了既定外部依赖，**When** 运行实际交付包，**Then** 不依赖开发目录或 Node 运行时显示设置和原业务入口。
2. **Given** Docker 未提供模型密钥或数据库暂不可达，**When** 启动后端，**Then** 设置静态资源可用，业务 readiness 为失败。
3. **Given** 普通自动化回归，**When** 未显式启用真实模型，**Then** 使用 Fake/Mock，不产生外部模型请求；付费验证有独立授权和评测记录。

### Edge Cases

损坏/未来版本配置、磁盘满或只读、并发保存、密文损坏/用户变更、超时/取消/限流、无密钥本地服务、已占用端口、缺前端静态资源、Docker NAT、过期授权、迁移中断、未知旧索引来源、密钥删除时仍被运行引用、恢复时旧 Prompt 不可用均须有明确错误与恢复路径。错误不得清空有效配置、伪造零分/向量、无限重试或自动切换供应商。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 建立显式 Development/Test/Demo 身份，隔离数据库、Redis、文件、配置、凭据、缓存、日志、临时目录和评测输出。
- **FR-002**: Test 写入与清理前校验实际目标及资源所有权；禁止回落非测试配置、删除非本次资源。
- **FR-003**: 默认值、已保存配置、受控开发输入和部署覆盖具有唯一、确定的优先级；逐字段显示实际来源。
- **FR-004**: 非敏感配置版本化持久保存，草稿、待重启和有效配置区分；损坏或升级失败保留原文件并进入可诊断状态。
- **FR-005**: 保存及激活具有原子性和并发修订检查；无效候选不覆盖最后有效配置，不静默恢复旧值。
- **FR-006**: Windows 密钥由后端安全存储，支持新增、替换、删除、失效识别、重录及重启；普通配置仅引用凭据。
- **FR-007**: Docker 凭据由外部 Secret 管理，界面只选择许可引用、显示状态和测试；不提供明文或暗中可写替代存储。
- **FR-008**: 密钥及数据库/Redis 密码、JWT 签名秘密不得进入配置读取响应、普通配置、浏览器持久存储、日志、错误、Audit、Trace、诊断或 Benchmark。
- **FR-009**: 界面选项由真实注册能力提供，覆盖默认 LLM、出题、主观阅卷、Reviewer、Embedding、Rerank、Vision、OCR 的适用性；未实现能力不可宣称可用。
- **FR-010**: 默认 LLM 加出题/阅卷覆盖；诊断、语义核验、拆题等已有文字任务明确继承默认，规则 Reviewer 无模型；可选能力缺失不阻塞无关任务。
- **FR-011**: 支持预设和自定义兼容服务的 URL、模型、凭据引用及有界高级参数；结构化、图像、向量、重排能力分别判断。
- **FR-012**: 连接检测使用固定最小输入，调用前告知可能收费并由用户触发；返回未填密钥、密钥无效、不可访问、模型不存在、限流、不支持能力、结构校验失败、成功，未知错误保留安全分类而不猜测。
- **FR-013**: 检测有超时、取消、并发和调用次数限制；测试失败不能改变有效配置，成功不等于长期在线或业务质量合格。
- **FR-014**: 模型、策略及任务绑定更新只影响新任务；核心依赖和本地运行资源变更标记待重启，禁止清全局缓存导致任务混用。
- **FR-015**: 每个新 AI 运行及可恢复检查点保存非敏感配置快照、真实 Provider/模型、Prompt/Schema 版本和凭据修订引用。
- **FR-016**: 暂停/重启恢复使用原绑定，缺原凭据/适配器/Prompt 时明确阻止相关 AI 调用；人工处理与原业务记录仍可查看。
- **FR-017**: 保持现有索引维度合同并检查同维度模型兼容；历史未知身份经受控入口查看、提供可核验证据、预览并确认接纳，保存操作者及前后状态审计；证据不足则停止新增摄取，不以当前配置补造历史、不自动重建。
- **FR-018**: Setup Ready 独立于数据库、Redis、模型和旧业务 JWT；设置自身不可用时不得声称 Setup Ready。
- **FR-019**: Business Prerequisites Ready先核对有效业务配置/JWT引用、数据库、必要迁移及结构、pgvector、Redis和持久目录；启动阶段据此前置条件装配原业务并调用原恢复钩子一次后才Business Ready。未装配进程修复/初始化后须重启；任一阶段失败保留/ready非成功。
- **FR-020**: AI Ready 按任务及其全部实际依赖计算，标明缺失/不支持/检测失败/未验证/可用及最近检测时间，不能只设全局布尔。Probe的10分钟期限仅限制新候选激活；已激活配置不因期限过去失效，禁止为持续使用定期自动付费检测。
- **FR-021**: 向导按检测→依赖诊断→目录/数据库→模型→检测→完成执行；允许返回修改、重启恢复和明确跳过 AI。
- **FR-022**: 核心配置不完整时阻止业务写入；模型缺失时只阻止依赖该模型的操作，禁止生成伪造结果。
- **FR-023**: Bootstrap 管理操作须验证本机部署边界、请求来源及独立操作权限，包含连接检测、凭据与初始化；安全GET/HEAD允许缺Origin但仍校验管理Token/Host，提供Origin则精确验证；敏感写入必须合法Origin。不能由公开页面自动授予权限。一次码过期、刷新/重开和会话到期须有Launcher/宿主管理入口重新授权路径，Token不持久化到浏览器。
- **FR-024**: 当前业务 JWT/RBAC/Admin/User 及原 API 保留；设置授权不授予课程、成绩、账号管理权限，模式选择不是认证替代。
- **FR-025**: 最小 PC 设置界面提供环境/依赖、默认及任务模型、凭据状态、连接结果、修改来源、待重启和诊断；旧业务可显式进入。
- **FR-026**: 所有配置规则、校验、保存、检测、就绪和授权由独立后端服务及契约承担，UI 不复制判定规则。
- **FR-027**: Windows 包包含设置静态资源，配置与业务文件持久外置；Docker 同样提供设置入口且不依赖模型预检才启动 HTTP。
- **FR-028**: 初始化区分外部依赖安装、配置、迁移和业务启动；不承诺免安装数据库/Redis，不执行自动删除或破坏性迁移。
- **FR-029**: 普通回归默认 Fake/Mock；真实模型评测显式启用并记录输入授权范围、运行配置、数据版本、调用及失败。
- **FR-030**: 配置变化保持客观规则评分、候选审核、考试内分值、人工复核、最终成绩、诊断来源和文件授权。
- **FR-031**: 业务备份仅包含非敏感配置/引用，明确凭据不随业务恢复；恢复后重新诊断，跨用户/主机须重新录入或提供外部 Secret。
- **FR-032**: 旧 .env 只经显式预览接纳，不自动改写或删除；新凭据写安全存储，旧来源留存事实及清理提示真实可见。
- **FR-033**: 未来测试修改必须先按既有框架记录 TCR，保留原合同断言；构建、运行、业务验收和发布证据分开记录。
- **FR-034**: 配置与诊断不收集业务题目/学生答案作为检测样本；本地模型检测无隐式下载，需下载时明确告知资源缺失。

### Non-Functional Requirements

- **NFR-001**: 安全验证以本机设置权限和凭据不泄露为边界；不引入公网账号体系，不声称抵御同一 OS 用户的恶意进程。
- **NFR-002**: 所有错误具有稳定代码、中文可操作提示和可定位步骤；不回传 SDK 原始响应、堆栈或秘密。
- **NFR-003**: 原子保存故障覆盖写前、凭据写后、配置指针切换前后；重启后存在一份可解释的有效修订或明确阻塞状态。
- **NFR-004**: 一次连接检测最多一个目标能力请求，默认超时 15 秒、允许 5–30 秒，服务端硬上限 30 秒；每环境最多 1 个付费检测在途，禁自动重试。
- **NFR-005**: PC 1366×768 与 1920×1080，中文标签、键盘可操作、非颜色唯一状态提示；密钥输入离开/提交后清空，不进入任何持久浏览器存储。
- **NFR-006**: 离线静态设置页面可用，无 CDN 必需资源；诊断慢依赖不阻塞设置导航。
- **NFR-007**: Provider/SDK 客户端资源有所有者与释放路径，结束检测、取消和运行退出均释放；不新建无限配置缓存。
- **NFR-008**: 评测记录保留实际身份与 unknown；Git SHA、构建号仅追溯，不新增跨组件相等门禁。

### Key Entities *(include if feature involves data)*

EnvironmentProfile（隔离身份及目标）、SettingsRevision（草稿/有效修订及来源）、CredentialReference（后端秘密引用和生命周期）、ProviderProfile（实际适配器/模型及能力）、TaskBinding（默认和覆盖）、ProbeResult（目标能力与时间/安全状态）、RuntimeSnapshot（运行使用的不可变事实）、OnboardingProgress（可恢复步骤）、ReadinessReport（设置/业务/逐任务状态）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Windows 首次使用验收全程无需手工编辑配置文件；全部向导步骤及一次关闭/重开能恢复。
- **SC-002**: 缺数据库、缺 Redis、缺模型密钥三种场景均能访问必要设置；所有未就绪业务请求均被准确拒绝。
- **SC-003**: 规定的八类连接检测结果均能被用户区分，失败/取消时原有效配置变化数为零。
- **SC-004**: 三环境各放置的哨兵数据、文件及秘密经 Test 清理后，非 Test 哨兵变化数为零。
- **SC-005**: 对正常、失败和取消路径的配置文件、响应、浏览器持久存储、日志、Trace、Audit、评测及诊断导出扫描，测试秘密原文出现次数为零。
- **SC-006**: 阅卷暂停→换配置→重启→恢复场景内，旧运行绑定变化数为零；新运行使用新绑定，缺原秘密时明确停止。
- **SC-007**: 不兼容维度及同维度不同模型切换均被阻止；原向量和历史结果变化数为零。
- **SC-008**: Windows 实际包与 Docker 各完成空配置、正常初始化、依赖失败、重启持久化和退出验收；结果分别记载，不以源码启动代替包验证。
- **SC-009**: 未授权、过期授权、跨源及错误主机名的管理写入和付费检测均拒绝；既有业务角色越权断言继续成立。
- **SC-010**: 普通回归对外模型请求数为零；显式真实评测保存完整来源与失败记录。
- **SC-011**: 两种 PC 尺寸下全部设置操作可用键盘完成，核心表单和错误说明可见；交付设置资源不请求外部 CDN。
- **SC-012**: 检测在 30 秒上限加 2 秒本地收尾内给出结果或明确超时，超时后不继续自动发起请求；记录实际值而不预填通过。

## Assumptions

单机、同一 OS 用户为本机设置授权主体；教师/学生业务身份本批不改变。Development 在 EXE 表示正式本地使用的默认工作环境，不默认开启 DEV_MODE；Test 与 Demo 是独立资源。数据库/Redis 已由操作者准备或使用既有 Docker 路径，向导不安装系统服务。真实云检测可能收费，仅用户显式触发。界面尺寸和 Probe 超时要求保持；EXE 启动时间按本次 MVP 决策作为优化目标，沿用原测量边界并记录实际值，不预填通过。
