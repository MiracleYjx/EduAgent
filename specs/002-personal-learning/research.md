## 2. Proposed Decisions and Alternatives

### P01 — 个人域与历史事实

**Design mapping**（方向按§4批准；具体实现建议仍为Proposed）：以 Subject/PracticeSession 替代旧课程所有者、考试发布/参与者语义；保留并改造题目、资产、文档、答案与 Workflow 组件。Question 稳定身份与 QuestionRevision、GradeAttempt 分开，旧练习引用具体修订，重练建立新作答，重评建立新轮次。

**Rationale**：E02/E06/E11—E14 说明旧域约束跨多个层；用户已明确不迁移旧业务，无需引入虚拟 Teacher/Student 维持旧入口。新域不是全后端重写。

**Alternatives considered**：仅改 Course/Exam 显示名成本较低，却会保留角色/参与者/整卷 final 语义；永久新旧双域增加维护和清理负担，不推荐。物理表重命名或复用可作为迁移手段研究，但不能改变新语义。

**Review / validation**：稳定知识点 ID、同题历史归并、题目修订与重评引用；迁移/FK/恢复 owner 映射必须真实 PG 验证。新在用记录保留不是旧业务备份。

### P02 — 有序图文与 DOCX

**Design mapping**（方向按§4批准；具体实现建议仍为Proposed）：题干、选项、解析使用有序类型块，图片仅持有 file_id/asset_id。文本索引与模型提示从块投影，不另存可独立修改的第二份题干。抽取层保留定位及疑点，再按学习资料/试卷用途分流。

优先验证 python-docx 配合有界 OOXML 读取，沿 Parser Registry 接入；PDF 渲染/OCR 从既有试卷链提取为可共用组件。公式与图片不能可靠转写时须保留可在 UI 核对的原内容；仅提供下载链接不算完成题目公式展示。

**Rationale**：E03—E05 的原页/文件机制可复用，但默认解析不覆盖 DOCX。官方 Document API 的 iter_inner_content 可按顺序遍历段落和表格；这不能证明浮动图和公式完整支持。[Document API](https://python-docx.readthedocs.io/en/latest/api/document.html)。官方图像说明对 inline pictures 有明确边界，因此必须单独验证浮动对象。[图片说明](https://python-docx.readthedocs.io/en/latest/user/shapes.html)。

**Alternatives considered**：Markdown 内嵌图初期简单，但选项归属、局部校正和图文疑点定位较弱。Office/LibreOffice 受控渲染后复用 PDF 可改善可视原文，但增加双平台体积、安装与进程依赖；若轻量方案不能满足必需内容，再提请选择，不自动引入系统级依赖。

**Review / validation**：DOCX 段落/表格/内联图/浮动图/OMML、扫描题图归属、跨页阅读顺序；不能把不支持复杂对象静默丢弃后标为成功。DOCX 使用真实段落/对象锚点，不捏造 PDF 页号。候选库版本与复杂公式渲染方案仍待批准；现有 Spike 工具环境已安装 python-docx 1.2.0/lxml 6.1.3，不构成生产依赖批准。

#### P02 Spike 对方案的约束

- **已有真实本地证据**：DeepCode 的 DOCX 回执为4项通过；有限 OOXML 样例为38,668 bytes、9个顺序块、2图，段落/内联图/浮动锚点图/单一上标OMML/表格均核对原XML锚点，图像字节与包内媒体一致。不支持的 pict 显式保留原对象及疑点。
- **能力边界**：python-docx 常规 text/inline_shapes 不涵盖浮动图和OMML；有限 walker 只实现一个上标公式，不代表任意OMML、VML/OLE/SmartArt、嵌套/合并表格或浮动页布局。生产注册表仍拒绝DOCX；Spike不是产品接入。
- **真实浏览器展示已核验**：在任务浏览器新建标签，经本轮独立127.0.0.1随机端口HTTP服务加载原有3178-byte HTML；未再尝试file:。两张160×60图片complete且自然尺寸正确，文字顺序、2×2表格与9个显示锚点均匹配原DOCX；MathML命名空间正确，指数2的实际布局高于且位于x右侧，截图可见x² + y = 7。页面无console error/warn。原HTML与既有有限解析器输出逐字节相同，图片字节与包内媒体相同，T002有限样例展示验收闭合；不代表生产DOCX或任意公式已经支持。
- **扫描/OCR事实**：DeepCode 的6项回执使用 RapidOCR 3.9.2/ONNX CPU及本地3个完整性核验模型。两页扫描PDF正文完整匹配为1/2、5/6行；同页PNG/JPEG为2/2行；400×300、JPEG25、旋转2度压力样例为2/6行。每页约0.64—2.10秒，仅为该合成样例的单机观察。整页CER混入额外图形标签，不可作为代表准确率。
- **不确定范围**：面积单位、上标、表格阅读序与选项图归属仍会出错。跨页测试只证明pending、原页/摘录及选项顺序协议；返回assets/source_regions为空，未验证真实题图归属。生产资料parser对该扫描PDF仍报DOCUMENT_NO_TEXT。
- **Proposed**：保留轻量有序解析路线；简单上标已验证，但复杂对象/任意公式和两平台展示仍需代表样例实测。不能可靠呈现时保留原DOCX对象/锚点及可用原图，提交受控文档渲染路线和Windows/Docker依赖成本供选择；不能缩减要求或自动安装渲染器。

### P03 — 内容准入、图片依据与评分

**Design mapping**（方向按§4批准；具体实现建议仍为Proposed）：显式 grounding 类型贯穿生成→核验→固定评分输入→评分。资料模式要求真实选定材料；通用知识模式以题目条件、有效参考答案/rubric及诚实来源构造上下文，不制造教材 chunk。

确定性硬失败包括结构错误、答案编码非法、资源不存在、分值非法；来源失败包括跨科目/错误版本/伪造引用；语义疑点包括条件不足、歧义、答案/解析矛盾和关键图像不清。不能判断的记录待核验，不能默认 pass。复用既有四类语义判定及来源白名单。

**Rationale**：E07 表明只修改生成入口不够；E08/E09 表明额外语义调用和教师确认都是旧假设。系统核验不要求用户提前看答案，也不伪造“教师已确认”。

**已确认方式与替代方案**：用户确认同次生成/补答案取得结构化答案依据与一致性判断，服务独立检查可确定的结构、来源、选项、分值及数据关系；模型判断如实标识，不能称独立或绝对正确性证明。有矛盾、缺依据或无法判断时暂缓，用户校正或主动复核，不自动追加第二次模型调用。没有采用自动疑点二次复核；强制每题第二模型和取消语义检查都不符合已确认范围。代表样例及质量验收标准仍需 Review，现有 Fake 只能证明流程与边界。

评分按已确认规则实现：单选/多选仅完全正确满分，主观按要点部分分，客观评分本身不调用模型。带关键图像的主观题必须有真实可用视觉依据；不能因 text Provider 不支持图片就删图评分。纯装饰或已可靠转写资产的依赖分类是待验证建议。

**代码差异与已确认规则（QD-018）**：旧提交拒绝空答案；用户现已确认空白文字主观题提示后允许继续整组提交，本地记零且不调用 LLM。未作答状态独立于分数；已作答有效零分、未作答本地零分和评分失败不可混同。统计方案 A 已确认：本组确定得分率含未答零分，作答完成率反映已填题数；选择题正确率和知识点诊断只用已作答有效记录，未答数单列，不占首次身份、20题窗口或5题门槛，在优先未做题中仍视为未做。此产品规则已批准，但表/字段及提交确认协议仍是 Proposed，源码尚未实现。

#### P03 Spike 与质量候选 — Proposed

现有质量Spike的28项通过、1项strict xfail与源码对应；Codex补充4个同次响应组合样例后，同文件最终为32项通过、1项既有xfail。新增封装仅存在于Spike，组合生产SemanticQuestionFields/SemanticMachineOutput、确定性字段检查及finish_validation；一次Fake返回后，pass保留待审核，fail/insufficient_evidence/needs_review暂缓，未增加第二次调用。不覆盖生产生成接线、真实来源准备、权限、数据库持久化或模型正确率。

生产确定性校验可拒绝未知chunk、非法答案编码、不可存分值及规范化重复选项；评分解析拒绝非法JSON、越界/非有限分数及置信度。关键图缺依据会前置拒绝。已作答有效零分可保留，但旧空白主观题仍拒绝，旧多选漏选仍给部分分，个人未答/争议合同尚未实现。

当前语义终局对空evidence_refs仍可能passed；旧生成payload不接收同次quality envelope；图表冲突样例编码合法而无图表一致性校验。Proposed质量样例必须包含这些反例；结构通过或模型自报pass不能消除实际矛盾，未知/缺依据保留待核验。图表轴/单位/数据/题设/答案须逐项对照，疑点不自动追加模型调用。真实模型语义正确率、主观评分及重评稳定性待G-Q定义样例、G-P授权实测。

### P04 — 收费操作与有限失败行为

**Design mapping**（方向按§4批准；具体实现建议仍为Proposed）：一个用户操作形成可检查的 OperationPlan/OperationRun，预览实际 Provider/模型、资料发送范围、派生步骤与已知估算，执行绑定同一配置事实。只保存必要状态和 usage/安全错误，不建设账户账单或充值系统。

AI 教师新会话首次收费发送确认、后续持续显示提示，模型/费用条件改变需重新确认。其他收费操作按已确认范围确认。未知估算明确未知，绝不显示“保证不超供应商账单”。

**Rationale**：E08/E15 显示自动逐题核验与应用重试可能造成额外调用。设置 Probe 的 allow_billable 不是完整业务授权。T237 benchmark 仅可借鉴发送前计数测试思路，其历史三次/¥0.15/指定模型不移植为产品限额。

**Alternatives considered**：只在 UI 弹窗后直接调用旧链无法覆盖派生调用；每次底层请求弹窗违背已选交互；完整计费平台超范围。推荐后端核验本次操作范围，幂等受理和逐步骤实际发送记录；新个人链注入不自动收费重发/不隐式切换模型的执行策略，不改全局旧策略掩盖合同变更。

**Review / validation**：Fake HTTP 覆盖未确认零发送、重复提交、并发、超时/断网结果未知、Schema失败、派生请求和 Lease 关闭。结果未知保持已尝试状态，不自动补发。保留已成功片段，用户重试说明将重做哪些部分；不因此承诺内置选页、自动批处理或恢复队列。

### P05 — 无业务登录的本地入口与维护

**Design mapping**（方向按§4批准；具体实现建议仍为Proposed）：个人资源的空间事实来自环境/数据根，统一服务依赖替代 user/teacher/student ownership。Windows 保持本地监听、Docker 宿主端口绑定本地；复用精确 Host/Origin 解析，业务写操作校验实际 Origin，JSON 与上传 multipart 按用途处理。

设置仍使用独立 Setup 授权。资源 GET 未必带 Origin，不能要求所有图片请求有 Origin；仍核对合法 Host、当前空间和真实资源/阶段。文件按 file_id 解析受管位置，不公开 storage。作答阶段不提前返回答案/解析数据及对应资产。

**Rationale**：E16 说明设置保护并非全局业务保护；E17 和 E02 显示维护/JWT 的真实耦合。

**Alternatives considered**：直接删角色校验会失去文件及维护边界；自动登录虚拟用户保留旧业务，不推荐；新增多用户认证系统违反单个人空间方向。

**Review / validation**：备份维护入口迁到现有本地管理授权，再清除无消费者的 JWT 必填/就绪约束；不自动删除仍被引用的凭据。Docker 内部0.0.0.0不代表外部可信 Host，映射规则必须有契约及真实部署验证。不同 Origin、路径越界、资源失配、阶段不符、凭据缺失保持真实失败。

### P06 — 教材版本、检索与 AI 教师

**Design mapping**（方向按§4批准；具体实现建议仍为Proposed）：沿用 DocumentChunk、pgvector/TSVECTOR、用途过滤与 IndexIdentityService。默认教材版本只影响新检索选择；历史引用固定具体版本/片段。无教材的通用知识练习不强求 Embedding；资料模式使用已显式配置的检索路径，不静默降级。

教师先复用 default_llm 绑定，记录用途为教师答疑；新增科目对话和上下文装配，不新增必须配置的 ai_teacher Provider 项。回答 Schema 包含正文、引用和不确定项，服务校验真实引用白名单；对话层没有成绩写入口。

**Rationale**：E10/E15 提供基础，未发现完整按科目持久对话；纯聊天不应绕过结构化引用校验。

补充已核对事实：settings/readiness.py:505 的业务就绪与逐任务 AI 状态分离，provider_registry.py:534 依据 retrieval_mode 给出 Embedding/Rerank 依赖。Proposed：新个人操作按实际 grounding 和所需步骤判断能力，通用知识路径不以未使用的检索任务阻断；不能为此静默修改已保存的检索配置或忽略本次实际必需的 Provider。

**Alternatives considered**：独立教师模型绑定可更灵活，但当前没有明确需求；新向量库或将整份历史发模型成本更高且违反已确认上下文边界。维护一个查询派生的诊断事实源，避免增加独立“掌握度真值表”。

**Review / validation**：新旧教材引用、版本过滤、关键词/向量已配置行为、跨科目引用拒绝、实际 usage 及无引用补充解释展示；正文来自模型不等于材料已证实。

#### P06 引用质量建议 — Proposed

真实确定性检查只能证明引用属于所给白名单，不能证明引用支持结论。T004的错引用反例、空引用缺口和缺关键图像拒绝应进入G-Q样例；通用知识依据不能伪造chunk以通过旧教材前置门禁。AI教师需要真实科目/版本/原文位置白名单与回答引用核对；本轮未实现或实测教师端到端能力。

### P07 — 组题算法与诊断投影

**Design mapping**（方向按§4批准；具体实现建议仍为Proposed）：先按科目、范围、题型、难度、来源、准入筛选，再无放回选择。均衡按覆盖较少知识点逐轮取题，同题只占一个位置、显示全部标签覆盖；同层随机打散。强化先取同知识点其他题，再穿插原错题，不定义固定比率。

首次/重练按稳定题身份区分；诊断只从已作答且评分有效、满足其他准入条件的记录投影。未作答数量单列，不直接形成弱点，不占首次有效作答、20题窗口或5题门槛，仍按未做处理；已作答有效零分仍计入。每题先除以本次满分再简单平均；近期最近20道不同题首次有效作答与此前最多20道比较；至少5题且均值低于60%才建议强化，其余按已确认规格展示。

**Rationale**：E06/E14 不能满足新规则；复用旧总分算法会把大分值题权重放大。

**Alternatives considered**：纯随机不能保证均衡；固定百分比已明确不采用；把重复作答算新题会虚增样本。多知识点分配优先级及稳定排序需要明确，但不新增精确掌握度模型。

**Review / validation**：真题优先与未做优先交叉时先展示两类不足及可选操作，不静默换 AI/重做；已存在历史的重复题合并保留所有作答，首次有效选择、重评不增加练习次数的规则须在数据合同核对。最近窗口排序建议按首次有效作答的提交时间和稳定 ID，不按重评时间刷成新练习。

### P08 — React、交付与验证限额

**Design mapping**（方向按§4批准；具体实现建议仍为Proposed）：已确认 React 统一方向下，科目路由提供资料/题库/练习/诊断；教师位于诊断页。原页/题块对照校正与共用块展示优先，暂不引入精细排版编辑器、WebSocket 或新的 UI 框架。

保留现有前端产物打包位置、Launcher/Bootstrap 和 Docker 生命周期；迁走必需 Gradio 业务后清理专属 import、冻结补丁和依赖。业务 OpenAPI 需显式扩展，目前生成链只覆盖 Settings。

## 8. 基础实现的适用边界

T009—T013只建立新域关系、操作记录/发送保护和DTO生成。新个人链按保存的RuntimeSnapshot通过ProviderRegistry构造客户端，SDK及应用重试均为0；发送前校验模型、端点、实际文本范围和字节，逐次持久计数并共用单一在途槽。读响应超限不能截断后冒充合法结果，超时/断连保留未知，成功片段保留。请求计数是已提交的发送尝试事实，无法证明供应商未处理或未收费。

真实传输默认关闭；仅Fake测试交通不需要G-P。将来真实发送还必须有可信G-P授权来源、模型专属输入/输出及费用预算、Token计数依据和用户确认。估算不替代供应商账单，不能继承已耗尽的v3.0授权。

解析相关临时值目前是共同配置；实际上传、DOCX/OCR/PDF/媒体执行接线仍在后续对应任务。复杂对象、真实评分、峰值内存、硬终止与双平台产品交付均未因本批基础实现而通过。
