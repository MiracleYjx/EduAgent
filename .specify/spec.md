## User Scenarios & Testing *(mandatory)*

### User Story 1 - 教师准备课程与考试 (Priority: P1)

教师负责管理课程、上传教学资料、查看学生成绩、查看 AI 阅卷结果以及查看知识盲点与学情分析。教师创建课程并上传教学资料，系统建立与课程关联的知识库。教师可以查看和管理知识库、管理题库，也可以按课程、知识点、难度、题型和数量请求 AI 生成候选题目。候选题目经过教师审核后才能进入题库并用于创建考试；对低置信度评分进行人工复核。

**Why this priority**: 这是教学评测闭环的入口，决定后续考试、阅卷和学情分析是否拥有有效的课程内容与题目。

**Independent Test**: 使用一个教师账号和一份受支持的课程资料，完成课程创建、资料上传、知识库建立、候选题目生成、教师审核和考试创建，并确认考试包含已审核题目。

**Acceptance Scenarios**:

1. **Given** 教师已登录且拥有一份 PDF、TXT 或 Markdown 教学资料，**When** 教师创建课程并上传资料，**Then** 系统完成资料处理并建立与该课程绑定的知识库。
2. **Given** 课程已经拥有可检索的知识库，**When** 教师指定课程、知识点、难度、题型和数量请求 AI 出题，**Then** 系统生成候选题目供教师审核。
3. **Given** 候选题目尚未经过教师审核，**When** 教师尝试将其直接发布或加入可用考试，**Then** 系统拒绝该操作并保持题目处于待审核状态。
4. **Given** 候选题目已被教师审核通过，**When** 教师将题目加入题库并创建考试，**Then** 系统保存考试及其题目关系，并允许后续符合条件的学生参加。

**v2.0 扩展用户旅程**: 教师分别使用“试卷导入”和“知识库导入”。前者将原试卷拆成待校正题目，后者提供教学依据；教师在原页与题目对照界面完成校正。没有答案的原题可以保存为待补全内容。教师按章节、知识点、题型、数量、难度和分值生成文字候选题或改编已有原题，查看来源、解析与核验问题，审核后按条件选题、调整题序、预览并发布考试。

**v2.0 Independent Test**: 使用一份文字试卷、一份含图扫描试卷和一份课程资料，分别完成原题导入、人工校正、资料摄取、知识库文字出题、原题改编、核验、教师审核和条件组卷。可单独验证导入与题库，不要求先完成学生答题。

**v2.0 Acceptance Scenarios**:

1. **Given** 教师上传有效的文字 PDF 或扫描件/图片试卷，**When** 系统处理该文件，**Then** 保存原文件、页图和来源页码，文字 PDF 优先文本提取、扫描内容使用 OCR，展示拆题进度及待校正结果；上传成功不会直接宣布正式入库完成。
2. **Given** 原题包含跨页题干、选项、图片或缺失答案，**When** 教师对照原页校正文字、题目边界、选项顺序、跨页内容及图片关联，**Then** 保留校正后的结构化内容与原页关系；确认后进入题库，缺答案题保持待补全且不能审核通过或用于考试。
3. **Given** 教师给定出题条件或选定待改编原题，**When** 系统生成候选题，**Then** 展示题目、答案、解析、评分要点、知识依据及核验问题；改编保留父题关系，条件变化触发答案、解析和评分标准重核验；依据不足明确缺失内容并阻止批准。
4. **Given** 题目已为 Approved，**When** 教师尝试修改内容、选项、参考答案、评分标准、题型或分值，**Then** 服务端拒绝并返回错误码、中文提示和当前状态；教师先退回 Needs Revision，再编辑并重新走审核流程。
5. **Given** 题库中存在已审核题目，**When** 教师按题型、数量、总分和知识点覆盖组卷，**Then** 展示已满足和未满足条件，允许调整题序、替换和完整预览；不满足时说明缺题或冲突，未校正或未审核题不能补位发布。

### User Story 2 - 学生参加考试并获得学习反馈 (Priority: P1)

学生查看自己可以参加的考试，在线完成客观题和主观题并提交答案。提交后，系统完成题型分流和评分，生成统一的考试结果；学生可以查看成绩、错题、AI 诊断以及知识点掌握情况。

**Why this priority**: 学生提交答案并获得反馈是平台直接交付学习价值的核心路径。

**Independent Test**: 使用一个已存在的课程、已发布考试和学生账号，完成查看可参加考试、答题、提交和查看结果，确认客观题与主观题均进入统一结果，且诊断信息可查看。

**Acceptance Scenarios**:

1. **Given** 学生拥有参加资格且存在可参加考试，**When** 学生查看考试列表，**Then** 系统只展示学生当前可以参加的考试。
2. **Given** 学生打开考试，**When** 学生填写客观题和主观题答案并提交，**Then** 系统保存答卷，并对每道题按客观题或主观题规则进行处理。
3. **Given** 答卷已经完成评分，**When** 学生查看考试结果，**Then** 系统展示成绩、错题与 AI 诊断，并展示知识点掌握情况。
4. **Given** 主观题评分置信度低于规定阈值，**When** 学生查看尚未完成最终复核的结果，**Then** 系统明确标记该结果处于待人工复核状态，不将未确认结果伪装成最终结论。

**v2.0 扩展用户旅程**: 学生参加含原题图片的考试，按明确题序查看题干、图示和表格。结果可查看时，学生能逐题查看自己的答案、评分解释、失分原因和相关知识点，并跳转到有来源的复习资料与可练习题目；待复核、依据不足和评分失败有独立状态说明。

**v2.0 Independent Test**: 使用一份已审核的带图题考试及实际学生答卷，验证考试与结果页图片对应、逐题解释与知识点关联、复习资料和练习推荐来源，不要求学生端具备图片生成或新的能力模型。

**v2.0 Acceptance Scenarios**:

1. **Given** 考试包含原题图示或表格，**When** 学生打开考试及可查看的逐题结果，**Then** 展示对应题目的正确图片、题序和本场考试有效分值；页图来源可追溯，缺失图片不会被静默替换或视为无图题。
2. **Given** 学生答卷已形成最终评分，**When** 学生查看诊断，**Then** 展示实际答案、逐题评分解释、失分原因及薄弱知识点，并提供关联课程资料和已审核练习题；推荐说明关联知识点及理由。
3. **Given** 评分尚未复核、模型失败或依据不足，**When** 学生查看结果，**Then** 明确展示对应状态，不把失败伪装成零分或已确定的知识弱点；没有合适资料或练习时说明原因。

### User Story 3 - 教师复核 AI 阅卷结果 (Priority: P1)

教师查看考试结果和 AI 阅卷详情。系统对客观题使用确定性规则评分，对主观题结合题目、标准答案、评分标准、学生答案和课程知识库检索结果进行 RAG + LLM 评分。评分结果必须结构化并经过校验；低置信度结果进入人工复核，教师可以确认或修改后形成最终结果。

**Why this priority**: 自动阅卷是本项目区别于普通考试系统的核心 AI 能力，人工复核保障低置信度场景下的教学可信度。

**Independent Test**: 准备同时包含客观题和主观题的答卷，触发评分并检查题型路由、评分依据、结构化结果和置信度；再构造低置信度结果，确认教师可以完成复核并生成最终结果。

**Acceptance Scenarios**:

1. **Given** 答案对应客观题，**When** 系统执行评分，**Then** 系统比较学生答案与标准答案并按规则给分，且不调用 LLM。
2. **Given** 答案对应主观题，**When** 系统执行评分，**Then** 系统以题目、标准答案、评分标准、学生答案和课程知识库检索结果为依据，经过 Query Construction、Hybrid Retrieval、Rerank、Grading LLM、Structured Output、Pydantic Validation 和 Confidence Check，生成结构化评分结果。
3. **Given** 主观题评分结果的置信度达到阈值，**When** 系统完成统一结果汇总，**Then** 该结果可以进入成绩和学生诊断报告。
4. **Given** 主观题评分结果的置信度低于阈值，**When** 系统完成 Confidence Check，**Then** 结果进入待人工复核状态，教师可以查看评分理由、知识点判断和建议并修改评分。
5. **Given** 教师完成低置信度结果的复核，**When** 教师确认或修改评分，**Then** 系统保存最终结果并将其纳入考试结果和学生诊断报告。

**v2.0 扩展用户旅程**: 教师查看含图题的原图、经核对的图片条件、学生答案和核验记录。评分使用发布时稳定的题目内容、答案、题图、知识点归属、本场有效分值及对应评分标准。客观题仍采用确定性规则，主观题使用可引用上下文；图像无法可靠理解时明确转人工核对。教师完成复核后，查看真实答卷的成绩分布、逐题得分率和知识点失分情况。

**v2.0 Independent Test**: 准备含客观题、带图简答题及待人工核对图像的答卷，验证图像上下文、有效分值、评分上限、复核及汇总一致；考试内改分属于本版验收范围，覆盖同题在不同考试使用不同分值及评分标准同比例换算的场景；规格纳入不等于功能已实现。

**v2.0 Acceptance Scenarios**:

1. **Given** 题目依赖图示或表格条件，**When** 系统准备评分输入，**Then** 提供原图及经核对的必要条件；无法获得可靠条件时标记依据不足或待人工核对，不凭空补全条件。客观题答案匹配仍不调用 LLM。
2. **Given** 已发布考试及其本场有效分值、评分标准已确定，**When** 评分或教师复核，**Then** 逐题分数不超过本场分值，客观规则、主观评分、总分和诊断使用同一份稳定的考试题目依据。
3. **Given** 同题在不同考试设置了不同的本场分值，**When** 系统评分，**Then** 按本场满分与题库原分值的比例换算评分标准和评分要点分值，使用本场满分约束结果，不沿用旧满分、不修改原题的题库分值。
4. **Given** 考试结果中同时存在正确答案、错误答案、待复核或失败记录，**When** 教师查看考情，**Then** 展示实际参与及提交情况、最终成绩统计和未完成状态数量，统计分母及知识点归属可核对，失败记录不按零分进入最终成绩。

### User Story 4 - 管理员维护基础运行秩序 (Priority: P2)

管理员维护用户和角色，并查看系统运行状态。管理员只负责基础管理，不参与课程、出题、阅卷等 AI 业务逻辑设计。

**Why this priority**: 基础用户和角色管理是平台可用的必要条件，但不应阻塞教师、学生和 AI 阅卷主流程。

**Independent Test**: 使用管理员账号分别执行用户管理、角色管理和系统状态查看，确认这些操作可用且管理员不能替代教师执行 AI 业务审核。

**Acceptance Scenarios**:

1. **Given** 管理员已登录，**When** 管理员管理用户或角色，**Then** 系统保存管理结果并按角色限制后续访问范围。
2. **Given** 管理员已登录，**When** 管理员查看系统运行状态，**Then** 系统展示基础运行状态。
3. **Given** 管理员尝试执行教师专属的 AI 出题审核或阅卷复核，**When** 系统校验操作权限，**Then** 系统拒绝该操作。

### Edge Cases

- 上传文件为空、损坏、格式不受支持或无法解析时，系统必须拒绝建立无效知识内容，并向教师说明失败原因。
- 资料解析后没有可用文本或没有形成有效知识片段时，系统必须提示教师，不得将空知识库视为建立成功。
- 知识库无法检索到与出题要求相关的内容时，系统必须明确提示检索不足，不得把无依据的题目直接标记为可发布。
- AI 出题结果无法通过结构化校验或题目校验时，系统必须将其标记为生成失败或待修订，不得进入已审核题库。
- 教师未审核 AI 候选题目时，任何发布、组卷或让学生参加的操作都必须被阻止。
- 学生重复提交、提交缺少必要答案或提交不属于当前考试的答案时，系统必须保留一致的考试状态并给出可理解的错误信息。
- 题目类型无法识别时，系统必须停止该题评分并标记为异常，不得把主观题当作客观题或反之。
- 主观题评分上下文不足、评分结果为空、结构化结果无效或置信度过低时，系统必须进入失败或人工复核状态。
- 客观题答案不匹配标准答案时，系统必须按确定性规则给分，不得使用 LLM 猜测分数。
- 管理员、学生或未授权教师访问其他角色专属功能时，系统必须拒绝访问。

**v2.0 新增边界场景**:

- 试卷文件损坏、扫描不清、文字层不可用或 OCR/拆题失败时，保留可用原文件及已完成结果，明确失败步骤和需校正项；不得把“文件已保存”当成“题目已入库”。
- 同页多题、跨页题、题号重复、选项顺序错乱、公式识别不确定或图片归属不明时，展示原页供教师校正；未确认内容不进入可用题库。
- 原题没有答案或评分标准时，可在人工确认来源与题干后进入待补全题目区；不能成为 Approved，也不能参与发布考试。
- 图像无法可靠理解或题图文件丢失时，保留真实状态、可用原图和关联记录，提示人工核对；发布前缺少必要题图或条件时阻止发布，考试中发现时标记异常交由教师处理，不让学生按缺失题干继续正常作答。
- 改编涉及题干、选项或图片条件变化时，旧答案、解析、评分标准及旧核验结论不能自动视为仍有效；候选必须重新核验并审核。
- 对 Approved 内容修改必须返回 `QUESTION_APPROVED_IMMUTABLE`、中文说明及当前状态；`difficulty`、`knowledge_points` 可维护，但已发布考试统计不能随题库元数据变化而改写。
- 组卷题库不足、约束互斥、总分不匹配或要求覆盖不存在的知识点时，逐项展示未满足条件及可调整要求；不得用未审核题补齐或静默降低约束。
- 历史文件已被系统临时目录清理、来源无法确认或迁移失败时，标明文件缺失/历史来源未知；不得伪造原文件、来源页码或成功迁移状态。
- 备份缺关联文件、恢复内容不一致或恢复失败时，明确不完整及失败原因，不把部分恢复宣布为完整恢复；原文件关联及业务记录必须可核对。
- 考试尚无答卷、最终评分不齐全或知识点没有有效观测时，展示“暂无数据”及有效样本数，不把无观测当作零分或已掌握。
- 云模型网络不可用、数据库/必要依赖不可用或启动配置不完整时，EXE 明确阻止进入正常业务就绪状态并说明原因，不误报启动成功。

## Requirements *(mandatory)*

### Functional Requirements

#### 用户与权限

- **FR-001**: 系统 MUST 支持用户注册或初始化用户。
- **FR-002**: 系统 MUST 支持用户登录，并使用 JWT 完成身份鉴权。
- **FR-003**: 系统 MUST 支持 Teacher、Student 和 Admin 三种角色。
- **FR-004**: 系统 MUST 按角色实施基础 RBAC，限制用户只能执行其角色允许的操作。
- **FR-005**: 系统 MUST 允许管理员管理用户和角色，并查看系统运行状态。
- **FR-006**: 系统 MUST 保持管理员基础管理与 AI 业务逻辑分离，管理员不参与 AI 出题审核或 AI 阅卷复核。
- **FR-007**: MVP MUST NOT 包含 OAuth、企业 SSO、多组织租户或复杂权限表达式。

#### 课程与知识库

- **FR-008**: 系统 MUST 允许教师创建、修改、删除和查看课程。
- **FR-009**: 系统 MUST 允许教师查看和管理知识库，并将知识库绑定到课程。
- **FR-010**: 系统 MUST 支持第一阶段上传 PDF、TXT 和 Markdown 教学资料。
  - **v2.0 补充**: 教学资料仍进入课程知识库并提供教学依据；试卷导入独立进入题库，二者入口、处理状态和来源类型必须明确区分（FR-041）。教学资料原文件纳入持久目录及备份恢复（FR-044、FR-045），不改变 v1.0 的受支持格式。
- **FR-011**: DOCX 支持 MUST 作为后续增强项，不得成为第一阶段主流程的必需条件。
- **FR-012**: 系统 MUST 按“文件 -> Document Parser -> Text Cleaning -> Chunking -> Embedding -> 知识库”的顺序处理教学资料。
- **FR-013**: 系统 MUST 保存每个知识片段的 `id`、`course_id`、`document_id`、`content`、`metadata`、`embedding`、`search_vector` 和 `created_at`。
- **FR-014**: 系统 MUST 使课程、知识库、资料和知识片段之间的关系可追溯，以便出题和阅卷引用课程上下文。

#### 题库与考试

- **FR-015**: 系统 MUST 支持以下题型标识：`SINGLE_CHOICE`、`MULTIPLE_CHOICE`、`TRUE_FALSE`、`FILL_BLANK`、`SHORT_ANSWER` 和 `ESSAY`。
- **FR-016**: MVP MUST 优先实现单选题、判断题和简答题。
- **FR-017**: 多选题、填空题、复杂主观题、编程题和图文题 MUST 作为后续扩展，不得阻塞 MVP 主流程。
- **FR-018**: 系统 MUST 允许教师管理题库中的题目。
  - **v2.0 补充**: 题库管理增加原题来源、解析、题图、校正和待补全状态，以及父题改编关系（FR-041 至 FR-047）。沿用 I01 的服务端约束：Approved 状态拒绝修改 `content`、`options`、`reference_answer`、`scoring_rubric`、`type`、`score`，返回 `QUESTION_APPROVED_IMMUTABLE`、中文提示和当前状态；`difficulty`、`knowledge_points` 允许修改。内容编辑须先 Approved -> Needs Revision，再编辑、提交审核并批准；不因 UI 可编辑而绕过服务端审核。
- **FR-019**: 题目 MUST 支持保存 `id`、`course_id`、`type`、`content`、`options`、`reference_answer`、`scoring_rubric`、`difficulty`、`knowledge_points`、`score`、`status` 和 `created_by`。
- **FR-020**: 系统 MUST 允许教师从已审核题目创建考试，并保存课程、题目、考试之间的关系。
  - **v2.0 补充**: 创建考试增加条件选题、显式题序、完整预览、原题图片复用及发布稳定性（FR-048、FR-049）。发布时每道题必须已审核且所需内容、答案、评分标准和图片完整；允许同一道题在不同考试设置不同分值，评分标准按本场满分与题库原分值的比例换算（已确认 D1）。
- **FR-021**: 系统 MUST 向学生展示其当前可以参加的考试。
- **FR-022**: 系统 MUST 允许学生在线答题并提交考试。
- **FR-023**: 系统 MUST 保存考试提交、学生答案、题目关联和对应评分结果。

#### AI 出题

- **FR-024**: 系统 MUST 接受教师指定的课程、知识点、难度、题型和数量作为 AI 出题条件。
  - **v2.0 补充**: 出题条件增加章节/资料范围和目标分值，保留课程、知识点、难度、题型和数量；教师选择“知识库生成新文字题”或“已有原题改编”。系统必须按所选课程与教学范围引用依据；条件不合法、依据不足或数量不足时说明原因，不能靠模型自行补造教学依据。
- **FR-025**: AI 出题 MUST 执行“教师输入需求 -> Query Construction -> 知识库检索 -> Question Generation Agent -> Pydantic Schema -> Question Validator -> 教师审核 -> 题库”的业务流程。
  - **v2.0 补充**: 保留原有检索、结构化输出、校验与教师审核链路，补充原题改编及可追溯父题关系（FR-046）、内容语义核验（FR-047）。新生成题目仅支持文字；原带图题改编需保留图并核对相关条件。生成内容、图像理解结果和核验结论经结构化校验后才可进入业务流程。
- **FR-026**: AI 生成结果 MUST 被标记为 Candidate Generation，而不是 Automatic Publishing。
- **FR-027**: AI 生成的候选题目 MUST 永远不能绕过教师审核直接发布、进入可参加考试或成为正式题库内容。
- **FR-028**: 系统 MUST 向教师展示候选题目及其审核状态，并支持教师审核通过或退回修订。
  - **v2.0 补充**: 候选审核展示题目、选项、参考答案、解析、评分要点、资料片段及来源位置、核验问题、审核状态和改编来源。核验失败或依据不足时说明缺什么；修订题干、选项、图片条件或其他影响答案的内容后，必须重核验答案、解析和评分标准。依据引用不是正确性证明，批准责任仍由教师承担。

#### AI 自动阅卷

- **FR-029**: 系统 MUST 对每份答案执行 Question Router，将题目分流为 Objective 或 Subjective。
- **FR-030**: Objective 题 MUST 使用确定性规则评分：学生答案等于标准答案时按题目分值给分，否则按规则给分；Objective 题不得调用 LLM。
- **FR-031**: Subjective 题的评分输入 MUST 包含题目、标准答案、评分标准、学生答案和课程知识库检索结果。
- **FR-032**: Subjective 题 MUST 按“学生答案 -> Query Construction -> Hybrid Retrieval -> Rerank -> Relevant Context -> Grading LLM -> Structured Output -> Pydantic Validation -> Confidence Check”的流程处理。
- **FR-033**: 系统 MUST 将客观题规则评分结果和主观题 RAG 评分结果汇总为统一考试结果。
- **FR-034**: Subjective 评分结果 MUST 是结构化结果，并且只有通过 Pydantic Validation 后才能进入统一结果、成绩或诊断报告。
- **FR-035**: 系统 MUST 对每个主观题评分结果执行 Confidence Check，并根据置信度阈值区分自动接受与待人工复核。
- **FR-036**: 低置信度主观题结果 MUST 进入 Pending Review 状态，教师 MUST 能够查看并人工确认或修改评分。
- **FR-037**: 教师完成复核后，系统 MUST 保存最终评分，并将其用于考试结果和学生诊断报告。
- **FR-038**: 系统 MUST 在评分完成后生成学生诊断报告，至少关联学生掌握情况、薄弱知识点、错误原因和学习建议。
- **FR-039**: 教师 MUST 能够查看学生成绩、AI 阅卷结果、知识盲点和学情分析。
  - **v2.0 补充**: 教师页补充 FR-050 的参与、提交、成绩分布、平均分、逐题得分率、知识点失分及需关注学生列表；必须来自实际答卷，展示统计分母、有效样本与失败/待复核数量，可回溯到学生、考试题目和知识点，不用模型生成数字替代统计。
- **FR-040**: 学生 MUST 能够查看成绩、错题、AI 诊断和知识点掌握情况。
  - **v2.0 补充**: 学生页补充逐题自身答案、评分解释、失分原因、对应题图、薄弱知识点、复习资料和已审核练习推荐（FR-043、FR-051）。失败、依据不足、答错和待复核分别展示；评分失败不直接记零分，不根据失败结果认定知识盲点。资料与推荐不足时明确说明。

#### v2.0 扩展功能需求（不回溯 v1.0）

- **FR-041**: **试卷导入与原题来源**。系统 MUST 提供独立于知识库的试卷导入入口，支持文字 PDF、扫描 PDF 和试卷图片，执行“保存原文件与页图 -> OCR/文本提取 -> 拆题 -> 结构化 -> 人工校正 -> 入库”。每道原题记录题号、题型、题干、选项、可获得的答案/解析/分值、课程及知识点、原试卷与页码关系。系统 MUST 展示处理进度、失败原因及待校正内容；上传成功不等于入库完成。缺答案原题经校正确认后可入库为待补全，补全与审核前不可用于考试。
- **FR-042**: **OCR 与人工校正**。扫描页 MUST 使用 OCR；可用文字 PDF 优先文本提取，无法可靠提取的页面转入扫描识别及人工核对。界面 MUST 将原始试卷页与结构化题目并排展示，允许教师修正文字、题目边界、选项顺序、跨页内容和图片关联。校正确认前保留为导入暂存内容，不能成为正式可用题目；校正确认与审核批准是两个不同步骤。
- **FR-043**: **原题图片理解、保留与复用**。系统 MUST 保存原图及对应题目/来源页关系，分析图示、表格和必要条件，保留理解结果及需核对标记；不可靠时保留原图并提示人工核对。组卷预览、学生考试、阅卷和逐题结果 MUST 展示对应原题图片；图片相关条件被修改时同步核对题干、答案、解析和评分标准。扩展首版 MUST NOT 生成新的题图或将新带图题自动发布。
- **FR-044**: **持久文件生命周期与历史引用迁移**。课程原文件、原试卷、页图、题图和导出文件 MUST 保存到应用管理的持久目录，数据库保存业务记录、元数据和文件关联；系统临时目录不得作为唯一长期存储。重启后文件及关联仍可访问。历史引用迁移 MUST 区分已迁移、文件缺失和来源未知，保留既有来源快照与真实状态，不回填虚假来源；受有效业务记录引用的文件不能被临时清理误删。
- **FR-045**: **数据库与关联文件一致备份恢复**。系统 MUST 支持将业务数据库记录与关联持久文件作为可核对的同一备份集备份和恢复。恢复后题目、原页、题图、资料、答卷及评分关系保持一致，并明确报告成功、缺失或失败；数据或文件不完整不得声明完整恢复。备份恢复覆盖历史迁移后的文件关联，不仅备份数据库。
- **FR-046**: **原题改编与父题来源**。教师 MUST 能从已有原题生成待审核改编候选，保留父题、原试卷/页图/图片及所用知识资料的真实来源；不覆盖父题内容。新知识库题与改编题必须可区分。改编目标须有教学依据，依据不足时说明缺失资料；原题本身不是可编造知识引用的理由。改编继承的图片条件和已变化的题干/选项须重新核验，批准后才可参加组卷。
- **FR-047**: **答案与条件语义核验**。系统 MUST 对候选题执行结构化检查及答案正确性、条件充分性、选项歧义、评分标准明确性的内容核验，输出分项结论、问题、理由、引用依据及人工核对状态。修订影响答案的内容后重核验答案、解析和评分标准，旧核验不能继续作为批准依据。存在未解决问题、关键依据不足或内容待补全时不得批准；教师修订或有依据地处置问题后才可完成审核。模型核验是辅助意见，不宣称保证所有题目正确。
- **FR-048**: **条件选题与组卷**。教师 MUST 能按题型、数量、总分和知识点覆盖从已审核题库选题，查看每项条件的已满足/未满足情况，调整题序、替换题目并预览完整试卷及题图。缺题、条件互斥或无法达到总分时明确说明缺口，允许教师调整要求；不得静默放宽条件或使用未审核题发布。发布前 MUST 检查要求满足且所选题目可用。
- **FR-049**: **显式题序、有效分值与发布稳定性**。每场考试 MUST 保存明确题序，并确定每题本场有效分值及对应评分标准；预览、学生答题、评分上限、教师复核、总分和诊断使用相同依据。同题 MUST 允许在不同考试设置不同分值，原题题库分值保持不变；本场评分标准和评分要点分值按本场满分与题库原分值的比例换算，客观题按本场分值给分，主观题使用对应换算标准并受本场满分约束。发布时的题干、选项、参考答案、解析、评分标准、题型、分值、题图和知识点归属 MUST 稳定，后续题库修订或元数据修改不得改变既有考试及历史结果。发布稳定策略已选择服务端冻结：Approved 内容不可修改，内容编辑必须先退回修订并重新审核，与 I01 一致；本版不引入题目版本或完整考试内容快照。已发布考试关联题目退回修订、元数据维护及题图变更的冻结生命周期须在 plan 中补齐，不能仅以 I01 已完成证明本条全部实现，亦不得静默降低历史稳定性目标。
- **FR-050**: **教师考情统计口径**。教师 MUST 查看参与/提交情况、最终成绩分布和平均分、逐题得分率、知识点失分及需关注学生列表。参与情况区分可参加、已参加及已提交；最终统计只用已完成评分与必要复核的实际答卷，未完成、失败和依据不足单独计数。逐题得分率为有效最终得分之和除以对应本场满分之和；知识点聚合展示关联题目、有效人数和分母，多知识点题的归属口径明确显示，不能重复累加成整场总分。平均分/分布注明有效答卷数；需关注学生说明具体失分或未完成原因。无有效样本时显示暂无数据。
- **FR-051**: **学生复习资料与练习推荐**。学生 MUST 能从最终评分的失分题和薄弱知识点查看关联课程复习资料及已审核练习题，展示资料来源、题目来源、关联知识点和推荐理由。推荐基于本人的实际答卷及可访问内容；不足时说明缺资料或缺题，不生成无来源推荐。原题带图可复用，待补全/未审核候选不能作为正式练习题；复杂学生能力模型不作为扩展首版前提。
- **FR-052**: **Windows EXE 交付与首次配置**。系统 MUST 增加 Windows EXE 启动方式并保留 Docker 开发/验收方式；教师双击后检查数据库、模型配置和当前必需服务，启动本机应用并打开界面。扩展初期连接已安装的本机 PostgreSQL（含所需 pgvector 扩展），数据库集成安装包不作为初期前提。数据与配置保存在持久位置，重启不丢失。数据库、模型或必需依赖未就绪时说明失败原因，不宣告业务就绪；云模型使用仍需网络，不宣称 EXE 等于模型离线。扩展首版 EXE 以单机为交付和验收范围，局域网共享考试作为后续选项；Redis 在核实用途及独立架构决策前保持现有依赖要求。

### MVP Scope Boundary

#### v1.0 文本 MVP（原验收边界保留）

本小节的原流程及排除项保持不变；图文题、试卷导入和 EXE 不成为 v1.0 收口的新增门槛。

第一阶段必须覆盖：

```text
教师上传课程资料
    -> 建立知识库
    -> 教师创建或 AI 生成题目
    -> 教师审核题目
    -> 创建考试
    -> 学生答题
    -> 提交答案
    -> 客观题规则评分
    -> 主观题 RAG + LLM 自动阅卷
    -> 结构化评分结果
    -> 生成学生诊断报告
    -> 教师查看考试结果
```

第一阶段不实现 OAuth、企业 SSO、多组织租户、复杂权限表达式，也不把 DOCX、多选题、填空题、复杂主观题、编程题或图文题作为 MVP 验收条件。

#### v2.0 扩展版边界

- 纳入 FR-041 至 FR-052，以及八项现有 FR 的扩展补充、US1 至 US3 的扩展场景和 SC-010 至 SC-014。扫描件 OCR 属于导入首阶段；优先保留单选、判断、简答三种基础题型并增加其原题带图理解、显示、复用与评分上下文。
- AI 新出题先支持有教学依据的文字题；原带图题理解与复用必须做，图像理解不可靠时人工核对。新题图生成、多选/填空/复杂主观题/编程题的完整交付不因本次扩展自动纳入。
- 基础考试、阅卷、人工复核和两类分析仍在扩展首版闭环内。高级图文检索、模型训练与复杂能力模型根据真实问题另行决策，不能把这些研究项变成基础闭环前置条件。
- PostgreSQL + pgvector、Provider 抽象、LangGraph 与 Gradio 保留；不切换数据库、不新增 Milvus/Elasticsearch 等独立检索服务、不绕过结构化输出规则。具体图像 Provider 能力与预算在计划阶段评估，业务不绑定具体供应商。
- Docker 开发方式继续保留；Windows EXE 补充交付，初期连接预装本机数据库。扩展首版为单机使用，局域网模式留作后续选项，不纳入本版验收；统一安装数据库、移除 Redis 或迁移前端均需另行决策。
- DeepSpeed、多模态微调、RLHF 和独立检索服务继续为后续研究方向；本次不修改宪章、不改变 v1.0 的 AI 优先原则及既有五条战略原则。

#### 跨功能 UI 验收约束（v2.0）

- 整体布局、导航、表格、筛选和操作风格参考 Ant Design Pro；教师题库、组卷、考试管理与阅卷流程参考考试星；学生首页、考试入口与学习结果组织参考 Canvas。这些是设计依据，验收以本项目实际可操作界面为准，不承诺未经确认的像素一致复刻。
- 公共界面 MUST 统一图标、字号、间距、按钮、状态和错误提示；主要导航与操作有一致图标及文字说明，待校正、待补全、待审核、已批准、待复核和失败状态可区分。
- 复杂页面 MUST 以列表、详情和显式编辑组织操作，减少同时展开的大表单；教师能从列表进入详情、开始编辑、保存或取消，且看见明确结果。试卷校正保留原页与题目并排，不因布局收敛丢掉校正依据。
- UI 验收按“试卷导入与校正 -> 知识库 -> AI 出题与审核 -> 组卷与考试 -> 阅卷 -> 教师分析 -> 学生首页与诊断”逐页查看运行效果及主要操作；Gradio 不足时另提具体前端迁移决策，不在本规格中默认替换。

### Key Entities *(include if feature involves data)*

- **User**: 使用平台的人员，具有身份信息和一个或多个受支持的角色。
- **Role**: Teacher、Student 或 Admin，定义用户可执行的操作范围。
- **Course**: 教师管理的课程，关联知识库、题目和考试。
- **Knowledge Base**: 与课程绑定的可检索教学内容集合。
- **Document**: 教师上传的 PDF、TXT 或 Markdown 资料，记录来源和处理状态。
- **Document Chunk**: 资料切分后的知识片段，包含 `id`、课程和资料关联、内容、元数据、向量、全文检索信息和创建时间。
- **Question**: 题库中的题目，包含题型、内容、选项、标准答案、评分标准、难度、知识点、分值、审核状态和创建者。
- **Exam**: 教师从已审核题目创建的考试，关联课程和题目，并定义学生可参加的范围或状态。
- **Submission**: 学生对一次考试的提交记录，关联学生、考试和提交状态。
- **Answer**: 学生针对单道题提交的答案，关联题目和评分结果。
- **Grading Result**: 单道题的客观或主观评分结果，记录得分、评分依据、结构化内容、置信度和复核状态。
- **Diagnosis Report**: 根据考试评分生成的学生学习反馈，包含掌握情况、薄弱知识点、错误原因和学习建议。
- **Review Record**: 教师对低置信度评分的人工确认或修改记录。

**v2.0 新增/扩展概念实体**（描述业务关系，不在本文件决定物理表或接口）:

- **PaperImport**: 独立试卷导入记录，关联教师、课程、原文件、处理阶段、页图、暂存题目、失败原因及校正确认；明确上传、处理、校正、待补全与入库的区别。
- **SourcePage**: 原试卷页，记录所属导入、页码、持久页图、文本/OCR 结果及需核对信息；一个题目可跨多页，一页可关联多题。
- **ImportedQuestionDraft / CorrectionRecord**: 尚未确认入库的结构化原题及人工校正记录，保存题边界、题号、字段内容、跨页关系、图片关联和确认状态；不是 Approved 题目。
- **QuestionAsset**: 题图或表格的持久原始资产及与题目、来源页的关联，包含说明、理解出的条件及人工核对状态，支撑预览、考试和阅卷复用。
- **Question 扩展**: 独立解析、原题导入来源、父题关系、待补全状态及内容核验记录；复用既有知识来源快照，不把无资料引用的导入题伪称有知识库依据。
- **QuestionValidationResult**: 候选内容对应的分项语义核验结果、结构化问题、证据、处理意见及人工核对状态；题目变化后旧结论不再作为当前批准依据。
- **ExamQuestion**: 一道题在特定考试中的关联，具有显式题序、本场有效分值、对应评分标准、题图和稳定的发布依据；支持考试内分值及同比例评分标准换算，发布采用已确认的服务端冻结策略；具体生命周期规则在 plan 中明确，不默认物理快照模型已经存在。
- **ManagedFile / BackupSet**: 应用管理文件及关联业务记录、历史迁移状态，以及可核对的一组数据库与文件备份；用于持久读取、缺失提示和完整恢复。
- **AssessmentAnalysis / LearningRecommendation**: 实际答卷与最终评分的统计视图及课程复习/练习关联，保留有效样本、统计分母、知识点归属与推荐理由；不要求新增复杂能力模型。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在使用一份有效课程资料、至少一名教师和一名学生的验收环境中，100% 的端到端验收运行都能完成“资料上传 -> 知识库 -> 出题或建题 -> 教师审核 -> 创建考试 -> 学生提交 -> 评分 -> 诊断 -> 教师查看结果”的完整路径。
- **SC-002**: 至少 90% 的首次使用教师能够在 15 分钟内完成课程创建、资料上传、候选题目审核和考试创建，过程中无需修改系统外的数据。
- **SC-003**: 至少 90% 的学生能够在首次进入考试后 5 分钟内找到可参加考试、完成答题提交，并在结果可用后找到成绩和诊断信息。
- **SC-004**: 对同一组客观题答案重复评分 100 次，结果必须保持一致，且客观题评分不得依赖模型生成意见。
- **SC-005**: 100% 的 AI 生成候选题目在教师审核前不得进入正式题库的可发布状态或学生可参加的考试。
- **SC-006**: 100% 的主观题评分结果都能被读取为统一的结构化结果；无法通过结构化校验的结果不得进入最终成绩。
- **SC-007**: 100% 的低置信度主观题评分都进入待人工复核状态；教师完成复核后，最终评分才能进入学生诊断报告。
- **SC-008**: 至少 90% 的验收参与者能够根据考试结果找到学生的成绩、错题、薄弱知识点、错误原因和学习建议。
- **SC-009**: 在权限验收中，Teacher、Student 和 Admin 三种角色的越权操作拦截率达到 100%。

#### v2.0 扩展版验收目标

下列指标是待实现目标，不是已有测量结论。验收资料由教师标注原题、页码、图片关联、标准答案及预期统计，记录样本与配置版本以便复测；不把人工校正后的准确率当成 OCR 自动准确率。

- **SC-010**: **原题可靠导入与校正**。验收集至少各包含一份文字试卷、含图扫描试卷和试卷图片，并覆盖跨页题、选项错序和无答案原题。100% 的已确认入库题能追溯原文件/页码，校正后的题干、选项及图片关联与教师标注一致；未确认题不进入可用题库，缺答案题不能批准。应用重启后，100% 的这些原文件和图片仍可访问。
- **SC-011**: **出题依据与答案核验**。在知识库新文字题与父题改编两条路径中，100% 的可批准候选均能展示教学依据、答案、解析、评分要点及核验状态；改编均能回溯父题。验收集分别覆盖答案错误、条件缺失、选项歧义、评分标准不明确及改编后旧答案失效，逐项确认核验记录、修订与重核验流程可用；100% 的仍有未解决问题或依据不足的候选不能批准，依据不足明确显示缺失内容。
- **SC-012**: **组卷、题图与发布稳定**。对条件可满足和不可满足的验收用例，100% 的发布考试满足题型、数量、总分和知识点覆盖要求，不可满足用例明确显示缺口。预览、学生考试、阅卷和结果页的题序、图片、有效分值及评分上限一致；完成题库修订或元数据维护后，100% 的既有考试及历史结果依据保持不变。考试内改分及同比例评分标准换算必须验收；发布稳定按服务端冻结策略验收，覆盖已发布考试关联题目退回修订与元数据变更场景，不以 Approved 守卫单独判定通过。
- **SC-013**: **可追溯考情与学习反馈**。使用同时含最终评分、待复核、失败和依据不足记录的实际答卷，100% 的参与/提交数量、成绩分布、平均分、逐题得分率和知识点失分与教师独立核算一致，统计分母可见。100% 的失败记录不作为零分或确定的知识盲点；学生逐题解释、薄弱知识点、复习资料和练习推荐可回溯实际答案及关联来源，缺资料/缺题明确提示。
- **SC-014**: **Windows 可运行、恢复与 UI 闭环**。在单机 Windows 验收环境、预装必要服务及有效模型配置下，100% 的交付验收运行可通过双击完成配置检查、应用启动与界面打开；缺必需配置/服务时均显示真实原因。对含课程资料、试卷、题图及答卷结果的一组备份执行恢复后，100% 的相关记录与文件关系可核对并访问；缺失文件不声明完整恢复。所列七类业务页面逐页完成列表/详情/显式编辑或对应查看操作，使用一致公共图标、字号、间距、按钮及状态提示，保留 UI 验收截图与操作记录。

## Assumptions

**v1.0 原有假设**（保持原适用版本）:

- 第一阶段只需要 Teacher、Student 和 Admin 三种角色；每个用户至少拥有一个角色。
- “可参加考试”表示考试已由教师创建并处于对目标学生开放的状态；复杂排课、组织和租户规则不属于本规格。
- 教师可以提供课程、知识点、难度、题型和数量等出题条件；系统不替教师自动决定未提供的教学目标。
- PDF、TXT 和 Markdown 是第一阶段的受支持资料格式；DOCX 支持作为后续增强项。
- 低置信度阈值由产品或项目负责人设定，并且在验收环境中保持可重复。
- 课程知识库能够为出题和主观题阅卷提供可引用的课程上下文；无法提供足够上下文时，系统必须暴露不足而不是静默编造。
- AI 候选题目和主观题评分都不是无需人工监督的最终结论：题目必须经教师审核，低置信度评分必须经教师复核。
- 第一阶段采用基础登录和 JWT 鉴权，不引入 OAuth、企业 SSO、多组织租户或复杂权限表达式。
- 学生、课程、题目、考试、答卷、评分和诊断数据在平台内可持久化保存，以支持结果查看和后续追溯。
- RAG、Hybrid Retrieval、Rerank、Grading LLM、Structured Output 和 Pydantic Validation 是本阶段 AI 业务流程的既定约束；具体供应商、模型和实现方案由后续计划阶段确定。


**v2.0 依赖与假设**:

- 教师提供真实试卷及课程资料，并负责校正、补全和批准；题目导入确认不替代审核，OCR 与模型核验不被视为无需人工监督的最终结论。
- 图像理解能力经可替换的 Provider 接入，输出经过现有结构化边界；图像不可理解时保留原图并请求人工核对，不因此切换技术栈或启动模型训练项目。
- 仍复用现有课程、题库、知识引用、审核、考试、阅卷、复核和诊断基础；实体新增不自动要求另建检索服务或重做既有来源快照。
- 统计取值以实际答卷与本场稳定依据为准；终态评分参与最终成绩，未完成状态单列。基础客观题确定性评分、主观题结构化校验和低置信度人工复核规则保持。
- Windows 初期外部数据库安装与模型账号/网络由运行环境提供；Redis 和 pgvector 等当前运行依赖必须在计划与交付中核实，未获独立决策不得静默移除。云模型不能以离线服务宣传。
- 原系统临时文件可能已丢失；历史迁移只能迁移实际存在且可核对的文件，缺失数据需补传或保留异常状态，不能承诺从无文件状态恢复原内容。
- D1、D2、D3 已确认：引入考试内分值、服务端冻结、EXE 单机优先。后续 plan、data-model、contracts 和验收设计需同步；分值换算精度与发布冻结生命周期在计划阶段明确。后续文档同步尚未完成，不把本文件变更当作架构实现或系统验收。
