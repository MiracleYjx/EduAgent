# EduAgent UI 布局设计与收敛评估

日期：2026-09-10。状态：布局方案待确认，尚未执行 `/speckit.implement`。

本方案以 PreSkool 的真实页面组织为参考，以 EduAgent 的教学评测闭环为功能边界。
本轮只新增本设计文档、向 `.specify/tasks.md` 追加布局细化任务，不修改应用代码。
后续实现仅限 `backend/app/ui/` 内视图文件，技术栈保持 Gradio，所有新增注释与界面提示使用中文。

### 1.1 共享外壳：P1-P7

截图可见浅色固定侧栏、白色顶栏及浅灰主背景。左上为标志与折叠按钮，侧栏顶部有学校选择，
底部有账号入口。选中的二级菜单使用浅蓝底和蓝色文字；内容区先给出页面标题与面包屑，
右侧放页面主操作。滚动主内容时，顶栏与侧栏保持可用。

实际侧栏按业务域分组，主要包括：

| 分组 | 可见菜单示例 | EduAgent 取舍 |
|---|---|---|
| Main | Dashboard（管理员、教师、学生、家长）、Application、Layouts | 保留角色概览；不照搬演示切换或模板设置 |
| People & Admission | Students、Teachers、Parents、Guardians、Staff、Users | 管理员仅保留用户和角色 |
| Academic | Classes & Sections、Subjects & Curriculum、Timetable、Learning、Examination | 转为课程、知识库、题库、考试、AI 出题与阅卷 |
| HRM、Finance & Accounts、Campus Operations | 人事薪资、考勤、缴费、财务、图书、交通等 | 不属于 MVP，不新增 |
| Communication | Broadcast、SMS、WhatsApp、Notifications、Automation | 仅借鉴消息入口，汇总已有状态和会话反馈 |
| Reports、Administration、Settings | 分析报告、AI Insights、活动、多学校、系统设置 | 保留已有授权的学情和基础运行状态，不增加多租户 |
| CMS & Pages、UI Interface、Help | 内容管理、组件示例、文档 | 不作为业务导航复制 |

顶栏可观察到全局搜索、语言、快速添加、主题切换、带数量的通知/消息、应用入口和用户头像。
EduAgent 采用“当前页搜索 + 消息与待办 + 当前用户 + 退出”的紧凑子集。搜索只处理已授权的当前页数据；
不新增跨实体搜索后端。面包屑位于内容标题行，快捷操作紧邻当前页面标题。

### 1.2 管理员仪表板：P1

截图首屏为标题/面包屑/期间筛选/导出/快速添加，其下是欢迎与操作区、出勤/招生/收费/考试指标。
向下包含班级分布、风险矩阵、出勤图、活动时间线等多种内容。可借鉴“概览指标先行、明细随后、
每一区有明确标题与入口”的层次，不采用其嵌套卡片、大面积欢迎区或财务校园模块。

EduAgent 管理员首屏使用用户数、启用数、角色数和依赖健康状态，避免让管理员进入 AI 审核流程。

### 1.3 教师工作台：P2

首屏展示教师头像/身份、当天安排、课程数量、作业待批阅数和快捷操作。下方依次存在课表、
教学信息、班级表现、课程摘要、作业、考试与评分、需关注学生、通知等区域。
“My Classes”按课程/班级展示人数、出勤率、平均分；“Assignments”分待批阅、已提交、逾期、
已评分等标签，列表每项带课程、提交进度和处理入口；“Exam & Grading”提供考试数量、
待录分数量和成绩概览。

截图中课表用带图标与文字的 Done/Live/Next 状态标识，已完成有绿色边框，正在进行可见红色 Live，
下一节可见黄色提示。EduAgent 采用“课程摘要 + 待办队列 + 最近考试 + 成绩概览”，
将最重要的候选审核和低置信度复核放在首屏可达位置，不增加排课与考勤功能。

### 1.4 学生工作台：P3

主内容围绕本人组织：个人摘要、学习指标、快捷入口、作业与任务、考试中心、最近结果、
科目表现、学习进度和学习建议。考试中心集中展示即将考试与最近成绩，减少寻找入口的成本。
本次截图仍保留了模板的通用后台侧栏，因此 EduAgent 会自行收窄为三个学生导航项，
不把管理功能暴露给学生。

该页适合借鉴“先看可参加考试，再进入结果与诊断”的组织方式；正式答题使用独立专注布局，
不能把大型仪表板直接当答题界面。

### 1.5 课程、考试与结果列表：P4-P7

P4/P7 均采用“标题和新建按钮 -> 搜索/筛选/列设置 -> 状态快捷筛选 -> 数据表 -> 分页”的顺序。
P4 的列围绕班级、状态、类别、教师、学生数；P7 的列围绕科目、教学信息、课程内容摘要和状态，
下部有课程进度及近期更新。它们是表格为主，课程内容在同一行内用短摘要压缩呈现。

P5 的表格按考试名称、日程、考试详情、状态与操作组织，快捷筛选包括已安排、进行中、
已完成、已发布和草稿。截图可见已安排为青色、已发布为粉色、已完成为绿色，配相应图标。
P6 的表格按学生、考试详情、结果、状态和操作组织，得分为“得分/满分 + 百分比 + 进度条”，
有已发布、待处理、通过、未通过、审核中等筛选；截图中已发布为绿色，通过为青色。

这些状态颜色在不同实体中并不完全一致。EduAgent 将建立自己的统一语义，
使用中文文字、图标和颜色共同表达，不直接复制 PreSkool 配色或新增其状态枚举。

## 3. 共享布局与交互规范

### 3.1 Gradio 组件及尺寸

| 区域 | 布局与组件 | 尺寸和行为 |
|---|---|---|
| 共享外壳 | `gr.Blocks`、`gr.Row`、`gr.Column`，视图内少量作用域 CSS | 桌面顶栏 64px，侧栏 216px，主区左右内边距 24px；不嵌入另一套前端 |
| 导航 | 分组标题 + Gradio 原生可交互导航控件 | 点击切换主区，当前项蓝色边线；底部为用户摘要和退出；多角色仅在授权角色内切换 |
| 页面标题 | 面包屑、标题、最多两个主操作 | 标题 22px，正文 14-16px，辅助文字至少 12px，字距为 0；字号不随视口比例缩放 |
| 摘要和课程卡片 | `gr.Markdown` / 只读 `gr.HTML` 展示，操作使用 `gr.Button` | 每行最多 4 个摘要，课程卡片最多 3 列，圆角不超过 8px；页面分区不包装成多层卡片 |
| 数据表 | `gr.Dataframe`、筛选 `gr.Dropdown`、当前页 `gr.Textbox` 搜索 | 默认 20 条/页，序号/状态/数值窄列，名称摘要宽列；选行绑定内部 ID，不让用户手工抄 ID |
| 详情区 | `gr.Column`、`gr.Markdown`、`gr.Accordion` | 长内容换行；标准答案、评分依据分节；原始业务内容按文本安全展示 |
| 编辑区 | 文本框、数值框、下拉框、单选/多选与开关 | 单选题选项逐项编辑；日期选择若当前版本不支持则退为日期与时分分开输入，不要求 ISO 字符串 |
| 图表 | 当前环境可用的 Gradio 图表组件 | 仅展示已有结构化结果，附可读数据表与单位；缺数据不画示例图 |
| 操作与确认 | 原生按钮 + `gr.Column(visible=False)` 确认区 | 选择、保存和确认不由静态 HTML 模拟；确认显示具体对象，确认前不调用写入操作 |
| 响应式 | 1200px 以上固定侧栏；768-1199px 收窄侧栏；768px 以下菜单折叠 | 小屏内边距 12px；管理详情上下排列；表格只在自身区域横滚，页面不整体横滚 |

项目只声明 `gradio>=5.0`，未锁定精确运行版本。实施时需先核对现有环境能力；
本方案不假设存在原生 Modal、侧栏、单元格按钮或富文本输入组件。确认区默认使用 Gradio
可见性切换实现内联双阶段确认，未来若验证已有版本支持可访问弹窗，再采用相同确认语义。
禁止为了实现布局引入新框架或修改依赖文件。

### 3.2 状态标识规范

基础色建议：蓝色 `#2563EB` 表示当前/操作/进行中，绿色 `#15803D` 表示成功/已完成，
琥珀色 `#B45309` 表示待处理/需关注，红色 `#B91C1C` 表示失败/危险，
灰色 `#64748B` 表示尚未开始/未知。背景采用对应浅色，主页面保持白色和中性浅灰。

| 状态 | 颜色与图标语义 | 中文文案与说明 |
|---|---|---|
| 未答 | 灰色空心题号 | “未答”，不以答案的真假值判空，判断题的“错误”是有效答案 |
| 已答 | 绿色勾与题号 | “已答”，表示已有作答内容，不代表回答正确或已保存 |
| 已标记 | 琥珀色旗标 | “已标记”，与已答/未答独立；只保存在当前答卷 UI 会话中，不冒充跨设备持久化 |
| 当前题 | 蓝色外边框 | 叠加在已有答题/标记状态上，不能覆盖这些状态 |
| 草稿 / 未知 | 灰色文档 / 问号 | “草稿”“状态未知”，不得默认成功 |
| 候选 / 待审核 | 琥珀色文档/时钟 | “候选题”“待教师审核”，尚不能直接成为可参加考试内容 |
| 待批阅 | 琥珀色时钟 | “待批阅”，表示排队评分，不与人工复核混同 |
| 处理中 / 已提交 | 蓝色进度符号 / 送出图标 | “处理中”“已提交”，已提交不代表评分完成 |
| 低置信度 / 待复核 | 琥珀色警告图标、徽标和横幅 | “低置信度，待人工复核”；显示实际值与已提供的阈值，不在 UI 中另设阈值 |
| 已评分、非最终 | 蓝色完成步骤图标 | “已评分，尚未最终确认”，是否最终以统一结果状态为准 |
| 审核通过 / 已确认 / 最终结果 | 绿色勾 | “审核通过”“已确认”“最终成绩”，分别匹配实体状态 |
| 退回修订 / 失败 | 琥珀色编辑图标 / 红色叉 | “待修订”与“处理失败”分开，说明可操作的原因 |
| 资料就绪 | 绿色勾 | “知识库已就绪”，只能依据真实 Ready 状态，不依据上传完成推断 |
| 运行状态异常 | 红色警告图标 | “异常”；无检查结果显示灰色“未检查”及更新时间 |

所有状态都带文字，不能仅靠颜色识别。原生组件没有图标能力时使用中文文字与边框作为稳定回退，
不为图标新增依赖。状态映射是显示层适配，不修改领域枚举和业务状态机。
题目与评分都可能有 Pending Review，但文案分别为“待教师审核”和“待人工复核”。

### 3.3 消息、搜索与上下文

消息面板从顶部展开，展示“类型 / 关联对象 / 状态 / 时间 / 查看”。教师看到本人的审核/复核待办，
学生看到自己的提交/结果反馈，管理员看到用户操作/健康检查反馈。只汇总已有授权数据和当前会话事件；
不新增邮件、消息推送、后台轮询服务、跨会话已读或永久消息存储。

顶部搜索标注当前对象，如“搜索课程”“搜索考试”“搜索用户”，不宣称能够全局搜索。
如数据只加载部分记录，文案与计数限定为当前已加载范围。点消息或快捷操作时携带已选课程/考试，
返回时恢复筛选、所选对象及滚动位置（在 Gradio 能力允许范围内），不悄悄丢弃未保存编辑。
