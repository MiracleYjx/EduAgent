# Demo 题目审核与重跑（T167，2026-10-03）

`python -m scripts.demo_seed` 和 `scripts/run_demo.ps1` 使用相同的真实业务服务。首次准备会创建开发账号、课程、知识库和示例题，摄取已有 `python_basics.md`；示例题送审后，由教师执行核验和批准。本脚本不自动批准题目、不新增文字模型核验调用。首次资料摄取仍使用当前已配置的 Embedding。

## 首次准备的真实返回

未全部批准时，种子命令成功完成准备并返回 `status=awaiting_teacher_review`、`question_states`、`awaiting_question_ids` 和后续操作提示；没有考试时 `exam_id`、`exam_status` 为 `null`。已有考试则返回其真实 ID 和状态，保持考试不变。此状态不会创建或发布考试，学生尚不能参加新的示例考试。

PowerShell 入口显示 `Demo UI running` 并提示按种子 JSON 判断考试是否可参加；服务启动和题目审核是两个独立状态。

## 教师操作

1. 在 `/gradio` 使用 `dev_teacher` 的开发模式快速登录，进入题库并选择 `[Demo v1] Python 基础` 课程。
2. 打开两道示例题。缺失评分标准的选择题先点击“编辑题目”，填写真实评分规则并保存。原示例题干、答案和短答评分标准由种子命令保留，教师自行核对。
3. 在“本次语义核验的教学依据”展开区点击“加载本课程教学片段”，从实际已摄取教材中选择本次依据。题目标签不能代替教学依据。
4. 如当前状态为草稿或退回修订，按实际界面完成修订并“提交审核”。点击“执行当前语义核验”，阅读真实报告；需要修订或依据不足时先处理并重核验，只有当前服务端允许批准时点击“审核通过”。
5. 两道题都已批准后，重跑 `python -m scripts.demo_seed`（Docker 环境可重跑 `scripts/run_demo.ps1`）。命令创建/保留草稿，缺本场评分核对时返回 `status=awaiting_exam_scoring` 及实际发布检查问题。
6. 进入考试管理的“发布检查”，选择实际题目，核对原 Rubric、基准及本场满分。客观题准备确定性满分标准；主观题明确输入真实数值要点或选择定性标准，阅读独立换算及尾差，填写最终值和真实确认理由。缺依据时保持待核对。
7. 所有题目的本场标准就绪后，再重跑种子命令发布，返回 `status=ready`、`exam_status=Published`，学生随后可参加。脚本不代替教师准备或确认标准。

## 幂等与生命周期

待审、待本场标准核对和已发布阶段重复运行均复用现有记录、Ready 教材、Chunk 和开发账号密码哈希，不重复摄取 Ready 资料。人工退回修订、已修改评分等字段保持原值，脚本不会再次送审退修题或替教师批准。已关闭或归档考试保持原状态，脚本报 `DEMO_EXAM_NOT_OPEN`，不会重开；考试题目被更改时沿既有 `DEMO_EXAM_CHANGED` 行为保留原卷。摄取失败仍保存真实错误，重试复用原文档。

本批聚焦测试仅使用真实隔离 PostgreSQL、实际教材摄取和受控 Provider 验证审核、幂等及生命周期；不把受控核验结果称为真实模型质量或独立教师标注。
