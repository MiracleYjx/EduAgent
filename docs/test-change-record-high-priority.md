# 第一批修复测试变更说明（TCR）

日期：2026-09-12。范围：已确认的 H03、H04、H05；M04 只核对任务文档。

本仓库使用 pytest、FastAPI TestClient 和 SQLite 隔离数据库，未发现单独的 TCR 模板。本记录遵循现有测试分层，不修改无关断言、不放宽权限或失败条件。

| 变更 | 必要性 | 覆盖内容 |
| --- | --- | --- |
| 扩展 `tests/unit/test_app.py` | 原测试只证明进程存活，不能证明依赖就绪 | `/health` 不调用依赖；`/ready` 的配置、数据库、Redis 检查顺序，成功 200、失败 503，失败原因脱敏及连接释放 |
| 新增 `tests/unit/test_config.py` | JWT 成为必填配置，必须验证启动边界 | 缺失、空白、少于 32 字符的密钥被拒绝；32 字符边界、默认配置、公开配置和校验异常不暴露密钥；不支持的算法与非法有效期被拒绝 |
| 更新测试配置及认证契约 | 移除旧的应用状态密钥注入，验证配置实际生效 | 通过 AppSettings 提供测试密钥；API 签名和有效期使用该配置；环境变量不能覆盖注入的配置；错误响应不包含密钥 |
| 新增 `tests/contract/test_exam_participation_contract.py` | 原测试没有考试分配范围，无法阻止跨学生参加 | 学生 A/B 的列表、详情、开始和提交边界；未分配考试向全体学生开放；中途撤销资格后草稿不能提交；分配唯一性和分配时间 |
| 调整 `tests/integration/test_m0_smoke.py` 和冒烟脚本 | Compose 必须使用真实依赖就绪状态 | 三容器启动、真实 `/ready` 返回 200、Alembic 升级和 Redis PING |

执行方法：先运行新增的聚焦用例确认能暴露旧实现问题，再完成实现；最终依次执行全量 pytest、mypy、Ruff、Compose 配置检查、容器启动和 `/ready` 验证，最后停止容器。结果写入审查报告的修复记录。
