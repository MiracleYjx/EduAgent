# 题库界面样板测试变更记录（TCR）

日期：2026-09-30；分支：deepcode。记录先于本次测试新增。

## 必要性与覆盖计划

本次将题库从常驻双栏编辑改为列表、题目详情和按需编辑三个界面状态。状态切换可能误开放已审核题目、误丢失编辑失败时的输入，或让审核作用于尚未保存的内容，因此需要测试真实注册的 Gradio 回调，而非 CSS 文本。

- 选择题目先展示只读完整题干、选项、答案与评分标准；内容安全转义，不隐藏复杂选项。
- 待审核题目允许显式进入编辑；编辑期间审核按钮关闭，保存后回到持久化详情。
- 已审核题目保持只读；未登录/非教师不能通过新增的编辑入口读取题目。
- 刷新/返回列表清理旧选择；查询失败保留真实错误，不显示旧统计为成功。
- 保存失败保留编辑状态与输入，不伪造成功；沿用既有题目保存、审核与删除合同。

验证：新增聚焦 UI 单元测试；运行既有 UI 测试、pytest tests/ -q、mypy backend/app/、ruff check backend/ tests/。另用本地 Gradio 预览验证列表、详情、编辑与桌面/小屏布局。没有可用 PostgreSQL 时，预览示例明确标识，数据库相关跳过与未验收内容如实记录。

## 会话状态补充（测试修改前）

界面状态新增后，原有退出流程只清理字段值，不能复位题库的列表/详情/编辑面板可见性。补充现有共享外壳测试，验证退出时回到列表并隐藏详情与编辑；只验证本次增加的状态，不改变原有会话和鉴权断言。

## 消息空态补充（测试修改前）

浏览器验证发现 Gradio 6 在 Accordion 展开时，子组件 visible 更新不能可靠同步，导致有消息时仍出现“暂无消息”。空态改为依据会话消息数量更新文本值，CSS 隐藏空文本，保持原有 Accordion 可见性与展开合同。补充两种回调结果测试：有消息时空态为空，无消息时明确提示；不修改原有消息权限或数据来源。
